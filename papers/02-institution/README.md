# 模块二 · 具名柜台设计学

**Module 2 · Designing the Attestation Counter**

**版本**：v0.3（草案）｜ **依赖**：第 0 篇《命名论文》、模块一《消融穿越类型学》 ｜ **性质**：消融面（Ablation Surface）研究的核心设计模块——为具名签署流（attestation flow）建造制度化设施。

---

## 摘要 / Abstract

本文提出具名柜台（Attestation Counter）的设计学：裁决（adjudication）是消融带上最稀缺的资源，稀缺资源需要计价与记账的设施。本文给出柜台的七个功能件（填单呈件、验单、柜台成本、挂账待决区、免审通道与退单、对账、坏账防护）的设计规范，诊断三种现行界面的"柜台病理"，提出五条设计原则与最小原型规格。本文的主张不是为 Agent 再造一个 harness，而是给裁决建造柜台——让人真正体会到 AI 价值的窗口，不在人看见 token 多忙，而在人看见自己哪一次签署留下了年轮（growth rings）。

**关键词**：具名智能（Onymous Intelligence）；具名柜台（Attestation Counter）；填单呈件（declaration slip）；挂账待决区（Suspense Zone）；坏账（bad debt）；免审通道（trusted lane）；设计原则（design principles）

## 第一命题 · 具名智能 Onymous Intelligence（总纲与本篇分工）

**总纲复述**（第 0 篇命题 0.1）：存在一种智能形态，其标志是每一个产生后果的动作都可归属于一个具名的裁决者——生产的可以匿名（anonymous），代谢的可以匿名，生效的必须具名（onymous）。

**本篇分工**：为具名智能提供**制度设施**（institutional facility）。语法（模块一）枚举了具名智能的命脉之流，但流不会自我组织——具名柜台是把具名签署流制度化的设施：填单使之可声明，验单使之可判，计价使之可持续，挂账使之不失效，对账使之可追溯，坏账防护使之不可伪造。判据 0.3 要求的"沿账回溯"，靠的正是柜台的账；没有柜台，具名智能只剩具名，没有智能的生效回路。

## 0. 引言：从皮肤到柜台（From Skin to Counter）

已有论断：Harness 由插件构成，界面是一个皮肤插件（skin plugin）。这个论断正确但不充分。皮肤只覆盖表面——它决定系统看起来如何，不决定**谁可以穿过、携带什么、留下什么**。

柜台是另一种东西。银行的柜台不是装修，而是制度：填单、验印、计价、隔离、放行、记账、追责，全在这个台面上发生。本研究的命题是：**消融面不应当是皮肤，应当是柜台**。最直接的影响还不是让人看见 token 效率，而是让人真正体会到 AI 的价值与新生产力——通过自己落下的每一笔签署。

## 1. 柜台的存在理由

**论证 1.1（稀缺资源论证，scarcity argument）**。消融带上，LLM 的生产是过剩的，Harness 的代谢是自动的，唯独特的裁决是稀缺的——它消耗不可再生的注意力，押上不可撤销的声誉。经济学常识：稀缺资源流经之处，必有计价与记账设施；没有设施，稀缺资源必被挥霍、截流或冒用。裁决的三种被挥霍形态即模块一的三阶蒸发（three orders of evaporation）。

**论证 1.2（无柜台的后果）**。没有柜台，裁决被蒸发（系统不记账）、被截流（默认通过）、被冒签（系统以人名义作数）。三者共同结果是：人不再是"会拍板的人"，而退化为"在场的观众"——具名性（onymity）消亡，三体退化为两体。

## 2. 七个功能件（Seven Components）

每个功能件按同一格式立档：功能、设计问题、失败模式。

### 2.1 填单呈件（declaration slip）

- **功能**：裁决前的显式声明——我判什么、依据什么、押上什么。
- **设计问题**：单子必须足够轻，使填写成本低于裁决本身的认知成本；又必须足够重，使 stake 显化。字段的极简集即穿越事件数据结构中的 `stake` 三元组。
- **失败模式**：单子膨胀为表格官僚主义——填单本身成为新的蒸发点（人开始不假思索地填单）。

### 2.2 验单（verification）

- **功能**：把待裁决的输出结构化呈现，使裁决成本最低、质量可审计。验单不是"展示输出"，而是"为裁决而组织输出"：差异高亮、依据溯源、风险点前置。
- **设计问题**：呈现流（presentation flow）的改造工程——从"发生了什么"转向"需要你判什么"。
- **失败模式**：验单沦为摘要——摘要替人预裁，裁决被架空为对摘要的追认（隐性截流）。

### 2.3 柜台成本（counter cost）

- **功能**：计价。每次裁决向人收取注意力成本，向系统返还裁决价值；柜台使这个汇率显化。
- **设计问题**：汇率如何定价？什么任务值得占用一次签署（高 stake），什么应当走免审通道（低 stake）？定价错误双向致命：什么都让人签 → 签署通胀（signature inflation），注意力枯竭；什么都不让人签 → 具名性消亡。
- **失败模式**：成本不可见——系统免费索取裁决（打扰式弹窗），或免费浪费裁决（签了无人引用）。

### 2.4 挂账待决区（Suspense Zone）

- **功能**：未裁决流的隔离。未入账的输出不得混入已入账流，不得生效为状态。
- **设计问题**：隔离的时效——挂账多久必须裁决？超期挂账如何升级（提醒、转签、还是显式作废）？作废本身也是一次须入账的具名事件。
- **失败模式**：挂账区变成灰色地带——未裁决的输出实际生效（隐性冒签），这是坏账的最大温床。

### 2.5 免审通道与退单（trusted lane & chargeback）

- **功能**：信任校准后的自动化直通（免审，trusted lane），以及把裁决退回上游重来的权利（退单，chargeback）。
- **设计问题**：免审的授权必须本身是具名的（谁、何时、依据什么批准了这条免审通道）；退单权不可剥夺——任何自动化不得堵死退单回路。
- **失败模式**：免审通道只增不减——信任一旦授予便无人复核，误判随时间累积（信任折旧 trust depreciation，模块三的仪表对象）。

### 2.6 对账（reconciliation）

- **功能**：裁决记录的可回放审计。具名者能随时回放自己的签署史：我签过什么、依据什么、后来怎样了。
- **设计问题**：对账视图必须回答"我的 stake 产生了什么复利"——这是人体会到 AI 价值的直接窗口，也是年轮可见化的界面层。
- **失败模式**：记录存在但不可回放（日志流陷阱：有账无柜台，记了但无人能判）。

### 2.7 坏账防护（bad-debt guard）

- **功能**：识别与隔离被稀释、被伪造、被冒签（forged attestation）的裁决。
- **设计问题**：坏账的计算化检测——凡 ledger_state 为"已入账"而缺 signer 或 stake 的记录，自动标坏账（模块一的形式化已使此可计算）。
- **失败模式**：坏账不被承认为坏账——系统把"默认通过"包装为"智能自动化"，这是最需警惕的修辞污染。

## 3. 反设计：三种现行界面的柜台病理学（Counter Pathologies）

| 界面形态 | 病理 | 诊断 |
| --- | --- | --- |
| 聊天窗 chat window | **无柜台** | 裁决与闲聊同渠，签署和废话共用一条流，裁决密度趋近于零 |
| 审批弹窗 approval popup | **有窗口无账** | 打扰式索取裁决，但不记账、不可对账、裁决无复利——免费索取稀缺资源 |
| 日志流 log stream | **有账无柜台** | 一切被记录，但无人能判、无人具名、无生效隔离——账本满仓，年轮为零 |

三种形态的共同根源：把界面当皮肤设计，不当柜台设计。

## 4. 设计原则（草案，Design Principles）

- **P1（可归属，attributable）**：每次裁决必填单，单子必落在具名者名下；匿名裁决不入账。
- **P2（成本显化，cost visibility）**：落笔即计价——每次请求签署时，向具名者显示本次裁决的成本与预期价值。
- **P3（未入账不生效，no ledgering, no effect）**：未裁决的输出隔离于挂账待决区，不得生效为状态；默认通过即冒签。
- **P4（退单权不可剥夺，inalienable chargeback）**：任何自动化不得堵死退单回路；免审通道的授权本身必须具名。
- **P5（年轮可见，ring visibility）**：账必须长在界面上——具名者随时可见自己哪一次签署留下了年轮。年轮不是后台报表，是消融面的一等公民。

## 5. 最小原型规格（Minimal Prototype）

**任务域选择**：选一个裁决密度天然高的真实任务流——候选：代码审查、研究核查、合同审阅。建议以研究核查为首个域（裁决结构最清晰：断言—证据—判定）。

**最小闭环**：填单 → 验单 → 签署/拒签/退单 → 入账 → 对账，五环齐备即为柜台；缺一即为皮肤。

**对照设计**：同一任务，皮肤式界面（聊天窗）对柜台式界面，测量组间差异：裁决质量、入账密度、年轮深度、具名者的主观价值报告（"我体会到我的判断改变了系统"）。

## 6. 开放问题

1. **形式主义风险**：填单一旦成为习惯动作，人开始不假思索地填单——柜台会不会制造出新的蒸发点？防形式主义的仪表是什么？
2. **古德哈特风险**（Goodhart risk）：年轮一旦成为指标，Harness 会不会学会伪造年轮？坏账防护如何防"造假账"?
3. **开柜台的资格**：谁有资格为一个任务域开设柜台？开柜台本身是否是一次须具名签署的事件？
4. **柜台的撤销**：一个柜台何时应当关闭？关闭柜台留下的账如何处理？
