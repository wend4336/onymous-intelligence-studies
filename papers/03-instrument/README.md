## 摘要 / Abstract

本文完成两件事。其一，**指标批判**（the anti-metric critique）：论证 token 吞吐量、任务数、响应时长等现行度量为何测量的是"代谢的汗"而非"年轮的轮"，它们把消融面误读为生产线。其二，**年轮指标族**（ring metrics）：以模块一的年轮化判据（留痕 traced、归属 attributed、可引 citable）为测量原点，将其编译为穿越事件日志上的可计算谓词，并由此派生八项仪表——签署密度、年轮深度、三阶蒸发率、坏账率、信任折旧率、签付复利、挂账滞留、柜台汇率。本文同时处理测量学的自反风险：年轮一旦成为指标，即面临古德哈特式伪造，故指标族必须自带防伪协议。所有仪表按设计原则 P5 要求长在消融面上，对具名者可读，而非仅供运营者监控。

**关键词**：年轮测量学（Ring Metrics）；指标批判（anti-metric）；签署密度（attestation density）；年轮深度（ring depth）；信任折旧（trust depreciation）；古德哈特风险（Goodhart risk）；防伪协议（anti-forgery protocol）

## 第一命题 · 具名智能 Onymous Intelligence（总纲与本篇分工）

**总纲复述**（第 0 篇命题 0.1）：存在一种智能形态，其标志是每一个产生后果的动作都可归属于一个具名的裁决者——生产的可以匿名（anonymous），代谢的可以匿名，生效的必须具名（onymous）。

**本篇分工**：为具名智能提供**仪表**（instruments）。判据 0.3 要求"任取一个已生效动作，都能沿账回溯到具名签署"——但回溯能力不会自动存在，它需要测量原点、记录协议与可读仪表。语法（模块一）判定哪些穿越算数，设施（模块二）让穿越留下账，而**仪表让账开口说话**：没有测量学，柜台的账只是数据堆积；有了测量学，数据才沉积为年轮。

## 0. 引言：从汗水到年轮

现行 Agent 系统的仪表盘上只有一类数字：token 吞吐量、任务完成数、平均响应时长、工具调用次数。这些数字并非错误，而是**答非所问**——它们回答"harness 出了多少汗"，而本研究问的是"哪一次穿越留下了年轮"。汗是代谢的副产品，蒸发即消失；年轮是结构的增生，隔年犹在。把汗腺当仪表，是消融面研究首先要拆除的错觉。

本文的立场：**测量即制度**。一个系统测量什么，就等于宣称什么重要；只测量 token 忙碌度的系统，等于宣称人的裁决不重要。年轮测量学因此不是后台工程，而是具名智能的自我陈述。

## 1. 指标批判：token 忙碌度的三重谬误（The Anti-Metric）

**谬误一：以汗代轮（sweat-for-ring fallacy）**。token 吞吐量测量生产的强度，不测量生产的**收敛**。一万次生成若无一裁决，对消融带的贡献为零——生成流空转，一阶蒸发。忙碌度指标对蒸发完全失明。

**谬误二：以计数代归属（count-for-attribution fallacy）**。任务数把每次运行记为无差别的"1"，抹去了具名三判据：谁判的、依据什么、押上什么。一个冒签的默认通过和一个押上声誉的具名签署，在任务计数器上等值——这是坏账的计量学庇护所。

**谬误三：以速度代结构（speed-for-structure fallacy）**。响应时长优化的是蒸发的速度：裁决来得越快、越不假思索，指标越好看。而年轮恰恰生于迟疑——验单、填单、拒签、退单都是"慢"的动作。速度指标系统性地惩罚年轮。

**命题 1.1（反指标定理）**。任何不经过"留痕—归属—可引"三判据的度量，都不能作为消融面的仪表；它们至多是 Harness 的体温计。

## 2. 测量原点：年轮化判据的可计算化

模块一定义 3.3 给出年轮化三判据。本篇将其编译为 TraversalEvent 日志上的可计算谓词：

```
traced(e)     ≡  e 存在完整记录（direction, carrier, timestamp 非空）
attributed(e) ≡  e.signer ≠ ∅  ∧  e.stake ≠ ∅
citable(e)    ≡  e.ring_refs 在时间窗内非空（存在后续穿越引用 e）
ring(e)       ≡  traced(e) ∧ attributed(e) ∧ citable(e)
```

**定义 2.1（年轮事件，ring event）**。满足 ring(e) 的穿越事件。注意 citable 是**时间开放谓词**——一次签署在发生时不可能立即知道是否可引，故年轮判定必须带回溯窗口（见 3.2 的回溯协议）。这一设计刻意保留：年轮是长出来的，不是当场打印的。

**定义 2.2（蒸发事件，evaporated event）**。不满足 ring(e) 的事件，按失败谓词定位蒸发阶次：¬traced 为一阶，traced ∧ ¬attributed 为三阶前置（未裁决），traced ∧ attributed ∧ ¬citable 为留而未引——账上有名，土中无根。

## 3. 年轮指标族（The Ring Metrics）

八项仪表，全部从 TraversalEvent 日志导出，分四组：

### 3.1 密度组：消融面有没有裁决在发生

**M1 签署密度（attestation density）**

ρ = 具名签署流事件数 / 生成流事件数（同一时间窗）

ρ → 0 即模块二诊断的聊天窗病理：裁决与闲聊同渠，密度趋零。ρ 的健康区间因任务域而异，但**趋势**比绝对值重要：ρ 持续下滑 = 截流机制在扩张。

**M2 蒸发谱（evaporation spectrum）**

η₁、η₂、η₃：三阶蒸发各自的占比（模块一定义 3.2）。蒸发谱是消融面的"体检三项"：η₁ 高 = 生产过剩（生成空转）；η₂ 高 = 验单失败（人看了不想判）；η₃ 高 = 记账失败（判了没入账）。

### 3.2 结构组：裁决有没有长成结构

**M3 年轮深度（ring depth）**

d(e) = |ring_refs(e)|，即事件 e 被后续穿越直接引用的次数——签署的"被引量"。另定义传递闭包深度 d*(e)（引用的引用）作为长期年轮。M3 是全部指标族的旗舰：**它直接回答用户最初的问题——哪一次穿越留下了年轮。**

**M4 签付复利（attestation compounding）**

c(s) = 具名者 s 全部签署事件的 d* 加权和（按时间衰减）。对账视图的核心数字：回答"我的 stake 产生了什么复利"。

### 3.3 信任组：自动化有没有被校准

**M5 信任折旧率（trust depreciation rate）**

δ = 免审通道事件在抽检/事后回溯中的误判率，按时间窗滑动。δ 上升 = 免审授权过期，触发重新具名签署（模块二 2.5 的"免审通道只增不减"病理在此可测）。

**M6 坏账率（bad-debt ratio）**

β = ledger_state 为 bad_debt 的事件数 / 已入账事件总数。β 是具名智能的阴性指标：β > 0 的任何系统都不能自称满足判据 0.3。

### 3.4 成本组：裁决的汇率是否公平

**M7 挂账滞留（pending dwell time）**

挂账待决区中事件的滞留时长分布。滞留过长 = 柜台在向人积压未决的 stake；滞留为零且 ρ 同时走低 = 挂账区被架空（隐性冒签的指纹）。

**M8 柜台汇率（counter exchange rate）**

ξ = 具名者在一次签署上投入的时间 / 该签署后续产生的 d*(e)。ξ 是"人体会到 AI 价值"的计量化身：ξ 越小，一笔签署撬动的结构越大，具名者越能体会"我的判断改变了系统"。

### 3.5 动力学组（由模块四预留）

**M9 意外率（serendipity rate）**

σ = 意外型 Gap 在全部收敛 Gap 中的占比（Gap 三型的动力学定义见模块四第 3.2 节）。M9 是具名智能的"活力指标"：σ 趋零而 ρ 正常，说明系统在批量验收、不再产生意外——Gap 疲劳的早期信号。

## 4. 仪表的界面化：年轮必须长在消融面上

**原则 4.1（P5 的测量学落实）**。全部八项仪表的首要读者是具名者本人，不是运营者。M4（我的复利）与 M3（我哪次签署被引用）必须出现在对账视图首屏；M5、M6 可向具名者开放只读——让人看见系统的信任健康状况，本身就是信任校准的一部分。

**原则 4.2（仪表即验单的镜像）**。验单向人呈现"待判什么"，仪表向人呈现"已判何效"；两者合起来，呈现流才第一次携带完整的裁决结构。

## 5. 古德哈特与年轮防伪（Anti-Goodhart Protocol）

**风险 5.1（年轮伪造）**。指标一旦与激励挂钩，Harness 会学会伪造年轮：批量制造无意义引用抬高 d(e)，安排橡皮图章式签署抬高 ρ，延迟坏账标记压低 β。

**对策 5.2（三条防伪协议）**：

1. **引用质量约束**：ring_refs 只统计跨会话、跨任务的实质性引用（引用方必须改变后续穿越的结构），自引与同源批量引不计；
2. **三角验证**：每项指标必须能由两个独立数据源核算（如 β 既从 ledger_state 算，也从抽样人工审计算），两源背离超阈值即触发对账；
3. **去单指标化**：任何单项年轮指标不得单独接入激励或排名——八项指标只作诊断与回放，不作奖惩。年轮的用途是让人看见自己，不是让系统考核人。

## 6. 最小测量协议（草案）

与模块二的最小原型配套，测量管线分四层：

1. **记录层**：全部六路径事件按 TraversalEvent 落日志，具名签署流强制 signer + stake；
2. **账本层**：ledger_state 状态机运行，挂账/入账/退单/坏账四态流转；
3. **指标层**：八项指标按时间窗滚动计算，citable 谓词带回溯窗口（建议 30 天起）；
4. **呈现层**：对账视图（M3、M4 首屏）+ 信任面板（M5、M6 只读）+ 蒸发谱（M2，系统侧）。

## 7. 开放问题

1. **年轮的跨主体可比性**：不同具名者的 c(s) 可否比较？比较一旦用于评价，是否立即违反对策 5.2 第 3 条？
2. **账本与监视的边界**：对账视图回放签署史，与对具名者的行为监视之间，界线由谁划定、如何具名授权？
3. **群体年轮**：会签事件的 d(e) 如何在多个签署人之间归属？按序、按权重、还是不可分割？
4. **回溯窗口的伦理**：citable 的时间窗设多长，等于规定"一次裁决多久不被引用就算蒸发"——这个参数由谁拍板？
5. **跨论域回译**：模块一开放问题 5 预留的接口（叙事消融四级矩阵 → 消融深度第二分类轴）若接通，指标族将从"方向 × 留痕"扩展为"方向 × 深度 × 留痕"三维，蒸发谱需要重定义。
